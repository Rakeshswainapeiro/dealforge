**Deliverable:** the TODO / work plan to close the gap between the **DealForge Phase 1 BRD** (docs/DealForge_Phase1_BRD Draft.xlsx, 88 requirements) and what is in the repository today, ending in a shippable Phase 1 MVP.

**Companion docs:** docs/DealForge_MVP_Release_Plan.md (delivery shaping, epics E0–E12), docs/DealForge_Requirements_Mapping.md (REQ-* to BRD), docs/UAT_Validation_DealForge.docx.

## 0. Scope decision and how to read this plan

The BRD defines **88 requirements**: **65 Must**, **20 Should**, **3 Could**. Three of the Musts are explicitly Later phase (WF-09 four-gate, OUT-04 IC memo, DSH-05 post-investment), leaving **62 Must for Phase 1**.

This plan takes **MVP = all 62 Phase-1 Must plus the 20 Phase-1 Should**, with the one Phase-1 Could (INT-12 duplicate detection) marked optional. That is deliberately wider than the existing docs/DealForge_MVP_Release_Plan.md, which scoped a narrower **Screening MVP** and deferred the financial, scorecard, output and reporting requirements. Section 3 reconciles the two: it sequences the wider BRD scope into slices and marks where the existing plan's epics already cover the work.

Status legend used throughout:

| Mark | Meaning |
|---|---|
| **Built** | Requirement satisfied end to end in code, with tests or UI evidence |
| **Partial** | A working slice exists; the BRD acceptance criteria are not fully met |
| **Gap** | No implementation found |
| **Deferred** | BRD itself marks the requirement for a later phase |
| **Process** | Delivery/documentation task, not application code |

Evidence index for the traceability column: server/rbac.js, server/abac.js, server/org.js, server/orgApi.js, server/auth.js, server/admin.js, server/audit.js, server/db.js, server/gate.js, server/pipeline.js, server/workflows.js, server/qa.js, server/themes.js, server/relatedParty.js, server/notify.js, server/storage.js, server/dataroom.js, server/features.js, server/config/*, src/pages/*, server/tests/*.

## 4. Definition of Done / UAT acceptance for MVP

The MVP ships only when all of the following hold:

1. **Every Phase-1 Must (62) is Built** and demoable; every Phase-1 Should (20) is either Built or formally deferred with Sirius sign-off; Later-phase items (WF-09, OUT-04, DSH-05, FIN-10, ADM-02) remain out of scope.
2. **Persona end-to-end journeys pass** in UAT, each with screenshot evidence in docs/uat-evidence/ and captured in docs/UAT_Validation_DealForge.docx: subsidiary preparer (submit complete / blocked / theme exception / withdraw), subsidiary CEO & CFO (attestation), Investment Analyst (screen, score, disqualify, clarify), Vertical Head (hard-filter override), Independent Reviewer (related-party sign-off), CIO (scorecard override), System Admin (config versioning, user admin), Leadership/IC (route stages). Per-TODO evidence follows the same convention (W1-13): `docs/evidence/<TODO-ID>/<persona>_<feature>.png`, and no TODO is marked Done in the tracker without it.
3. **BRD acceptance criteria** for each closed requirement are reproduced in the UAT script, including the negative cases: incomplete submission blocked (DOC-03), out-of-appetite stopped (INT-02), greenfield without funding blocked (INT-10), un-cleared disqualifier blocks progression (SCR-05), internal comment invisible to subsidiary (AUD-03), sibling isolation (PLT-02), tampered memo fails QR (OUT-03).
4. **Non-functional gates pass**: security scan clean (NFR-02), performance SIT (NFR-04), backup/restore rehearsal (NFR-05), browser SIT (NFR-06), usability UAT (NFR-07).
5. **CI green**: npm run lint, server node --check, full server suite (server/tests/, about 136 tests) and npm run build.
6. **Deployable** via Docker/compose with the documented backup/restore runbook.
7. **Release notes plus guides** published: subsidiary "how to submit" and Sirius "how to screen".
8. **No open Sev-1/Sev-2 defects**; each with a named owner.
